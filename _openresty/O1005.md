---
layout: pitfall
title: "cjson encodes an empty table as an object, not an array"
permalink: /o/O1005/
description: >-
  Lua has a single table type, so `cjson` cannot tell an empty array from an
  empty object and encodes `{}` as `{}` by default. An API contract that
  promises `[]` can silently return `{}` instead, breaking strict JSON clients.
platform:
  - OpenResty
runtime:
  - LuaJIT
---

```lua
-- handler.lua
local cjson = require("cjson")

ngx.say(cjson.encode({}))   -- {}
```

The same value could mean an empty list or an empty map, and `cjson` chooses
the object form. To flip the default for the whole process, call
`encode_empty_table_as_object(false)` before encoding:

```lua
local cjson = require("cjson")
cjson.encode_empty_table_as_object(false)

ngx.say(cjson.encode({}))   -- []
```

This is a global setting, so it changes every other encoder in the worker;
prefer per-value control when only one field must be an array. Assign the
`cjson.empty_array` userdata to force the array form:

```lua
local cjson = require("cjson")

ngx.say(cjson.encode(cjson.empty_array))   -- []
```

When the table is not always empty but should still encode as an array while
it is, tag it with the `cjson.empty_array_mt` metatable:

```lua
local cjson = require("cjson")

local t = {}
setmetatable(t, cjson.empty_array_mt)

ngx.say(cjson.encode(t))      -- []
t[1] = 123
ngx.say(cjson.encode(t))      -- [123]
```
