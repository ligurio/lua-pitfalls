---
layout: pitfall
title: "Forgetting return before ngx.exit() keeps the handler running"
permalink: /o/O1001/
description: >-
  `ngx.exit()` stops the current request by raising an internal error, so the
  call must be prefixed with `return`. Without `return`, an enclosing
  `pcall()`/error handler can catch that error and execution continues,
  leading to a second response or corrupted output.
platform:
  - OpenResty
runtime:
  - LuaJIT
---

```lua
-- handler.lua
local function handle()
  if not authorized then
    ngx.exit(ngx.HTTP_UNAUTHORIZED)   -- forgot `return`
  end
  ngx.say("top secret")               -- may still run after the exit attempt
end
```

`ngx.exit()` uses `error()` internally, so it does not act like a `goto`:
unless the call is the last expression of a `return`, an enclosing `pcall()` or
error handler can resume execution. Always use `return ngx.exit(...)`:

```lua
local function handle()
  if not authorized then
    return ngx.exit(ngx.HTTP_UNAUTHORIZED)
  end
  ngx.say("top secret")
end
```
