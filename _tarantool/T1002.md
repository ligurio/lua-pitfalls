---
layout: pitfall
title: "Yielding inside a Tarantool transaction aborts it"
permalink: /t/T1002/
description: >-
  In Tarantool's default transaction mode, any yield (for example
  `fiber.sleep`, a blocking network call, or a yielding DML operation) inside
  an active transaction aborts it with "Transaction has been aborted by a
  fiber yield". Yields are allowed only when the MVCC engine is enabled.
platform:
  - Tarantool
runtime:
  - Lua 5.1
---

```lua
box.cfg{listen = 3301}

box.atomic(function()
  box.space.tickets:replace{1, 429}
  fiber.sleep(1)                 -- yield inside the transaction
  box.space.tickets:replace{2, 429}
end)
-- error: Transaction has been aborted by a fiber yield
```

A transaction is a set of statements that must not interleave with other
fibers. In the default mode Tarantool enforces this by aborting the
transaction as soon as the current fiber yields. Moving the yield outside the
transaction avoids the error:

```lua
fiber.sleep(1)
box.atomic(function()
  box.space.tickets:replace{1, 429}
  box.space.tickets:replace{2, 429}
end)
```

Since Tarantool 2.6.1 the MVCC transaction manager
(`box.cfg{memtx_use_mvcc_engine = true}`) allows yields inside memtx
transactions. Leaving a transaction open when a request returns is also an
error: "Transaction is active at return from function".
