description: >-
  `io.open(name, "r")` returns a read-only handle. Calling `:write()` on it
  fails with "file not opened for writing" (or "Bad file descriptor"), often
  exactly on the error path that was supposed to log something.
runtime:
  - Lua 5.1
  - Lua 5.2

  - semgrep

```lua
local fh = io.open("app.log", "r")
fh:write("started\n")
-- Runtime error: app.log: Bad file descriptor
```

Open the file with a write-capable mode. The mode string determines the allowed
operations:

```lua
local fh = io.open("app.log", "w")   -- truncate and write
fh:write("started\n")
fh:close()
```

`"r"` and `"rb"` are read-only, `"w"`/`"a"` are write-only, and a trailing `+`
(`"r+"`, `"w+"`, `"a+"`) opens the file for both reading and writing. Opening
with `"r"` and then writing is a common mistake when a log line is added later.
