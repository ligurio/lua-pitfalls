---
layout: pitfall
title: "Lua scheduling is cooperative: a long computation blocks everyone"
permalink: /p/L1090/
description: >-
  Lua has no preemptive scheduler. Coroutines and Tarantool fibers switch only
  at explicit yield points, so a function that runs for a long time without
  yielding stops every other task in the same VM until it returns.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local function crunch(data)
  local sum = 0
  for i = 1, #data do
    sum = sum + data[i]
  end
  return sum
end

-- In a fiber or coroutine, nothing else runs until crunch() returns.
local f = fiber.create(function()
  local total = crunch(huge_table)   -- no yield inside: blocks the thread
  fiber.sleep(0)
end)
```

Context switches happen only where the code explicitly yields: `coroutine.yield`,
`fiber.yield`, `fiber.sleep`, or a function that implicitly yields (a socket
read, an HTTP call, `fio`). Any pure-Lua loop keeps the thread busy in between.

Break long work into chunks and yield between them, so other tasks get a turn:

```lua
local function crunch_chunked(data, chunk)
  local sum = 0
  for i = 1, #data, chunk do
    for j = i, math.min(i + chunk - 1, #data) do
      sum = sum + data[j]
    end
    fiber.yield()          -- let the scheduler run other fibers
  end
  return sum
end
```

Yielding is not free, so keep chunks large enough to amortize the switch. The
same cooperative model means that an FFI call into native code that blocks (see
[L1083]({{ '/p/L1083/' | relative_url }})) or a blocking `io.*` call
([L1032]({{ '/t/T1032/' | relative_url }})) freezes the whole VM.
