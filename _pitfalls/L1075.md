title: "A missing table field is nil, not an error"
permalink: /p/L1075/
description: >-
  Indexing a table with a key it does not have returns `nil` instead of raising.
  A typo in a field name therefore goes unnoticed until the `nil` is used, when
  it fails at an unrelated line with a confusing error.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - emmylua-analyzer
---

```lua
local config = {
  host = "localhost",
  port = 8080,
}

print(config.hostname)   -- nil: 'hostname' is a typo for 'host'

print(config.host .. ":" .. config.port)     -- "localhost:8080"
print(config.hostname .. ":" .. config.port)
-- Runtime error: attempt to concatenate a nil value (field 'hostname')
```

Reading an absent key is legal and yields `nil`; only using that `nil` later
fails. Field-name typos, renamed fields and data coming from another source all
produce the same delayed error, which points at the use of the value rather than
the access that introduced `nil`.

Validate the table once, where it enters the program:

```lua
local function make_config(opts)
  assert(opts.host, "config.host is required")
  assert(opts.port, "config.port is required")
  return { host = opts.host, port = opts.port }
end
```

EmmyLua's `undefined-field` diagnostic catches accesses to fields that are not
declared on an annotated table, turning the typo into an error at the access
site. See also [L1006]({{ '/p/L1006/' | relative_url }}) for the same problem
with globals.
