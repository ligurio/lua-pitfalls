---
layout: pitfall
title: "ffi.stash hides object lifetime in a global registry"
permalink: /p/L1093/
description: >-
  ffi.stash stores a value in a process-wide table keyed by a name. It is
  intended for libraries that must keep an object alive across calls, but in
  application code it hides ownership, defeats the garbage collector, and makes
  the lifetime of native resources hard to reason about.
runtime:
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local ffi = require("ffi")

local function get_buffer()
  return ffi.stash("buffer")    -- returns whatever was stored under this name
end

local function init()
  -- The buffer is never collected while the stash entry exists.
  ffi.stash("buffer", ffi.new("char[1024]"))
end
```

The name is global to the process, so unrelated modules can collide on it, and
nothing records who stored the value or when it may be released. Prefer an
ordinary upvalue or a module-level local for lifetime management; the collector
then releases the memory when the owner becomes garbage:

```lua
local ffi = require("ffi")

local buffer                      -- owned by this module

local function init()
  buffer = ffi.new("char[1024]")
end
```

When a destructor is required, attach one with `ffi.gc` and keep the owning
cdata reachable (see [L1078]({{ '/p/L1078/' | relative_url }}) and
[L1065]({{ '/p/L1065/' | relative_url }})) instead of relying on a global
stash.
