---
layout: pitfall
title: "table.insert and table.remove do not validate positions in 5.1/LuaJIT"
permalink: /p/L1070/
description: >-
  In Lua 5.1 and LuaJIT a bad position passed to `table.insert` or
  `table.remove` is accepted silently and creates a hole or a huge sparse
  table. Lua 5.2 and later raise "position out of bounds", so the same code is
  quietly broken on LuaJIT/Tarantool and errors on newer Lua.
runtime:
  - Lua 5.1
  - LuaJIT
---

```lua
local t = {1, 2, 3}

table.insert(t, 99, "x")   -- 5.1/LuaJIT: accepted, t[99] = "x"
print(#t)                  -- 3 or 99: the length is undefined for a sparse table
print(t[4])                -- nil: index 4 is now a hole

table.remove(t, 99)        -- 5.1/LuaJIT: returns nil, no error
```

The position argument is easy to mistype, for example by passing the length or
an index from another array. On Lua 5.2+ the same calls fail loudly:

```lua
-- Lua 5.2+:
-- bad argument #2 to 'table.insert' (position out of bounds)
-- bad argument #1 to 'table.remove' (position out of bounds)
```

Keep positions within `1 .. #t + 1` for `insert` and `1 .. #t` for `remove`,
and prefer the forms that append or remove the last element:

```lua
table.insert(t, "appended")     -- no position: appends at #t + 1
local last = table.remove(t)    -- no position: removes the last element
```

If the position is computed, check it explicitly so LuaJIT and Lua 5.2+ behave
the same way:

```lua
local pos = 1
assert(pos >= 1 and pos <= #t + 1, "invalid insert position")
table.insert(t, pos, "value")
```
