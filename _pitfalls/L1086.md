title: "The order in which expressions are evaluated is undefined"
permalink: /p/L1086/
description: >-
  Lua does not specify the order in which the subexpressions of a statement are
  evaluated. Code that relies on the left-to-right order of function calls with
  side effects (printing, mutating a shared table, incrementing a counter)
  produces different results on different interpreters.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local log = {}

local function f()
  log[#log + 1] = "f"
  return 1
end

local function g()
  log[#log + 1] = "g"
  return 2
end

local x = f() + g()
print(table.concat(log, ","))   -- "f,g" or "g,f": not guaranteed
```

The reference manual fixes the order only for a few constructs (for example,
the right-hand side of an assignment is evaluated before the assignment, and
logical operators short-circuit left to right). The evaluation order of
operands, arguments and table fields is otherwise unspecified, so an
interpreter is free to choose.

Do not depend on evaluation order for side effects. Evaluate the calls into
separate statements when the order matters:

```lua
local a = f()
local b = g()
local x = a + b
```

The same caution applies to multiple results and to arguments of a call: the
order in which the arguments are evaluated is not defined. See
[L1012]({{ '/p/L1012/' | relative_url }}) for how multiple results are
truncated.
