---
layout: pitfall
title: "unpack() stops at the first nil"
permalink: /p/L1060/
description: >-
  `unpack` (or `table.unpack`) walks a list until the first `nil` and returns
  only the values before it. A single missing element therefore truncates the
  result and silently drops everything after it.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local t = {1, nil, 3}

print(select("#", unpack(t)))   -- 1
local a, b, c = unpack(t)
print(a, b, c)                  -- 1  nil  nil
```

The length of a table with holes is undefined, and `unpack` uses that length.
Pass the range explicitly to include values after the hole:

```lua
local a, b, c = unpack(t, 1, 3)
print(a, b, c)                  -- 1  nil  3
```

Avoid sparse arrays in the first place. When a table may contain `nil`,
`table.pack` records the real length in its `n` field, which can be passed to
`table.unpack`:

```lua
local packed = table.pack(1, nil, 3)
print(table.unpack(packed, 1, packed.n))   -- 1  nil  3
```

`table.pack`/`table.unpack` exist from Lua 5.2; on Lua 5.1 and LuaJIT use
`unpack(t, i, j)`.
