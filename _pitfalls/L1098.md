---
layout: pitfall
title: "not x == y negates x, not the comparison"
permalink: /p/L1098/
description: >-
  Unary `not` binds tighter than comparison operators, so `not x == y` is
  parsed as `(not x) == y`. The comparison operators are also left-associative,
  so `1 <= x <= 3` is parsed as `(1 <= x) <= 3`. Neither is the intended test.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local x = 5

if not x == 5 then
  print("x is not 5")
end
-- `not x == 5` is `(not x) == 5`.
-- `not x` is `false`, and `false == 5` is `false`, so nothing is printed
-- even though x is 5.

if 1 <= x <= 3 then
  print("in range")
end
-- `1 <= x <= 3` is `(1 <= x) <= 3`.
-- `1 <= x` is `true`, and `true <= 3` raises
-- "attempt to compare boolean with number".
```

The Lua reference manual lists unary operators (`not`, `#`, `-`, `~`) above the
comparison operators, and comparison operators associate to the left. Write the
negation as `~=` and combine chained comparisons with `and`:

```lua
local x = 5

if x ~= 5 then
  print("x is not 5")
end

if 1 <= x and x <= 3 then
  print("in range")
end
```

Parentheses make the current parsing explicit if the "not of the comparison"
was really intended: `if not (x == 5) then ... end`.
