permalink: /p/L1056/
description: >-
  Modules are usually required once, at load time. Calling `require` inside a
  function repeats a package lookup on every call and hides the module
  dependency inside the function body.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep

```lua
local function handle(req)
  local json = require("json")    -- runs on every call
  return json.decode(req.body)
end
```

`require` does not re-read the file after the first call, but it still performs
a package-table lookup and a function call each time, and it hides the module
dependency inside a function body. Move it to the top of the file:

```lua
local json = require("json")

local function handle(req)
  return json.decode(req.body)
end
```

A lazy `require` is justified only when the module is optional or expensive and
is not needed on every path; in that case cache the result in an upvalue, so the
lookup happens once. A circular dependency can also make a top-level `require`
fail, but the fix is to break the cycle rather than to move `require` into a
function.
