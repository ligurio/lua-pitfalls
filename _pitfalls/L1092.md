---
layout: pitfall
title: "LuaJIT inlines only small functions"
permalink: /p/L1092/
description: >-
  LuaJIT's compiler inlines short, frequently called functions into their
  callers, but it gives up on functions that are too large or too branchy.
  Moving a helper out of a hot loop can silently stop it from being inlined and
  make the code slower than the inline version.
runtime:
  - LuaJIT
---

```lua
-- A small helper is a good inlining candidate: the JIT folds it into the loop.
local function scale(v)
  return v * 3 + 1
end

local function sum(data)
  local s = 0
  for i = 1, #data do
    s = s + scale(data[i])
  end
  return s
end
```

Inlining happens at trace recording time. The compiler has a limit on the size
of an inlined callee and on the total trace length, so turning `scale` into a
large function (or adding branches and calls to other functions) removes it
from the trace and replaces a fused computation with a call. Whether a function
is actually inlined also depends on the arguments and the loop it is called
from, so it is not a property you can assume from the source alone.

Measure instead of guessing:

```sh
luajit -jdump script.lua      # show traces and inlined calls ('INLINE' markers)
luajit -jv script.lua         # log trace aborts and why they happened
```

Keep hot helpers small and free of calls that abort a trace. See
[L1058]({{ '/p/L1058/' | relative_url }}) for the operations that are never or
only partially compiled, which also prevent inlining.
