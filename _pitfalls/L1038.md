---
layout: pitfall
title: "require() caches modules, so edits are not picked up"
permalink: /p/L1038/
description: >-
  `require` loads a module once and stores the result in `package.loaded`
  under the requested name. Later `require` calls return the cached value, so
  changing the file on disk has no effect until the cache entry is cleared or
  the process is restarted.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local first = require("mymodule")
-- edit mymodule.lua on disk here
local second = require("mymodule")

print(first == second)   -- true: the cached table is returned
```

`require` keys the cache by the string passed to it, so the same file reached
under different names (`mymodule`, `mymodule.lua`, `./mymodule`) can be loaded
several times, while any edit to an already-loaded module is ignored.

```lua
package.loaded["mymodule"] = nil   -- drop the cache entry
local fresh = require("mymodule")  -- reloads from disk
```

Clearing `package.loaded` is a development convenience; avoid it in
production, where re-running a module's initialization can duplicate state.
See also [L1022]({{ '/p/L1022/' | relative_url }}).
