---
layout: pitfall
title: "A local declared without a value is nil"
permalink: /p/L1053/
description: >-
  `local foo` creates `foo` and initializes it to `nil`. Reading it before the
  first assignment silently propagates `nil` instead of raising, which usually
  hides a typo or a shadowed variable rather than being intentional.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
  - luacheck
---

```lua
local foo

if foo then
  print(foo)
end
-- The branch is never taken because foo is nil, but nothing indicates
-- whether that was intended or foo was simply never assigned.
```

Initialize the variable together with its declaration, and use `nil` only when
an uninitialized value is genuinely wanted:

```lua
local foo = nil          -- explicit

local total = 0
for i = 1, 10 do
  total = total + i
end
```

The problem is worse when a variable is read far from its declaration: the
`nil` travels through the program and only surfaces later as an error such as
"attempt to perform arithmetic on a nil value".
