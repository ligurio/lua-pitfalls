---
layout: pitfall
title: "table.sort() needs a strict order function"
permalink: /p/L1036/
description: >-
  The comparator passed to `table.sort` must define a strict weak ordering:
  `cmp(a, b)` is true only when `a` must come before `b`. A non-strict
  comparator (for example `a <= b`, or one that always returns true) makes the
  sort raise "invalid order function for sorting" or produce a wrong order.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local t = {3, 1, 2, 5, 4}

table.sort(t, function(a, b)
  return true   -- always "a before b": not a valid order
end)
-- Runtime error: invalid order function for sorting
```

The comparator must be irreflexive (`cmp(x, x)` is false), asymmetric and
transitive. Two common mistakes are returning a constant and using `<=`
instead of `<`:

```lua
table.sort(t, function(a, b) return a <= b end)   -- wrong, though it often works
table.sort(t, function(a, b) return a < b end)    -- correct
```

Sorting an array that contains `nil` (a hole) fails as well, because the
comparator is eventually called with `nil`:

```lua
local sparse = {1, nil, 3}
table.sort(sparse)
-- Runtime error: attempt to compare nil with number
```

See also [L1004]({{ '/p/L1004/' | relative_url }}) and
[L1017]({{ '/p/L1017/' | relative_url }}) about arrays with holes.
