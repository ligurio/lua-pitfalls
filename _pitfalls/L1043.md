---
layout: pitfall
title: "Errors returned by pcall are silently ignored"
permalink: /p/L1043/
description: >-
  `pcall` never raises: it returns `false` plus the error instead. Code that
  drops the second value, or checks only one of the two, turns a hard failure
  into a silent one and loses the only diagnostics about what went wrong.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local ok, err = pcall(process, job)
-- both results are discarded: the caller has no idea the job failed
return

-- ...

local ok, err = pcall(process, job)
if ok then
  return
end
-- err is dropped here too, so the reason for the failure is lost
```

Either inspect `err` and act on it, or do not use `pcall` at all and let the
error propagate:

```lua
local ok, err = pcall(process, job)
if not ok then
  log(("process failed: %s"):format(tostring(err)))
  return nil, err
end
```

Checking `ok` and the error together is the common bug: `if ok then ...`
handles the success path, but the failure path still needs `err`.
