  `__tostring` should return a string, `__len` an integer that can be used as a
  length, and comparison metamethods a boolean. Lua often does not check these
  results, so a wrong type shows up later as a confusing error or a silently
  wrong value.
runtime:
  - Lua 5.1

Each metamethod has an expected result type, but Lua does not always enforce
it. A metamethod that returns `nil`, a float, a string or a table can therefore
"work" for a while and then fail far from its definition.

## `__tostring` must return a string

```lua
local Account = {}
Account.__index = Account

function Account.new(name)
  return setmetatable({name = name}, Account)
end

function Account:__tostring()
  return self.name          -- nil when the account has no name
end

local a = Account.new()
print(type(tostring(a)))
-- Lua 5.1 / 5.2 / LuaJIT: "nil" (tostring returns the bad value as is)
-- Lua 5.3 / 5.4 / 5.5: error: '__tostring' must return a string
```

`print` checks the result and fails on every version, although the message
differs:

```lua
print(Account.new())
-- Lua 5.1 / 5.2 / LuaJIT: error: 'tostring' must return a string to 'print'
-- Lua 5.3 / 5.4 / 5.5: error: '__tostring' must return a string
```

Return a string explicitly, or validate the field:

```lua
function Account:__tostring()
  return tostring(self.name)          -- "nil" instead of nil
end
```

Numbers are sometimes accepted because they can be coerced to strings, so
`return self.balance` may appear to work. In Lua 5.2 and later `tostring`
converts a returned number to a string; in Lua 5.1 and LuaJIT `tostring`
returns the number as is, and only `print` displays it. Either way it violates
the contract and breaks as soon as the field is not a number.

## `__len` should return an integer

The length operator itself does not enforce this: in Lua 5.2 and later it
returns whatever the metamethod produces. The integer requirement comes from
the code that consumes the length, such as `table.insert` and numeric `for`.

```lua
local Queue = {}
Queue.__index = Queue

function Queue.new()
  return setmetatable({items = {}, n = 0}, Queue)
end

function Queue:push(v)
  self.n = self.n + 1
  self.items[self.n] = v
end

function Queue:__len()
  return self.n / 2         -- 1.5: a float, not a length
end

local q = Queue.new()
q:push("a"); q:push("b"); q:push("c")

print(#q)                   -- 1.5 on Lua 5.2+; 0 on Lua 5.1 and LuaJIT

for i = 1, #q do
  -- Lua 5.2-5.5: one iteration instead of three
  -- Lua 5.1 / LuaJIT: no iterations at all (#q is 0)
  print(q.items[i])
end

table.insert(q, "d")
-- Lua 5.1 / LuaJIT: silently writes q[1] = "d", because #q is 0
-- Lua 5.2: silently writes q[2] = "d"
-- Lua 5.3-5.5: error: object length is not an integer
```

On Lua 5.1 and LuaJIT `__len` is not consulted for tables at all, so `#q`
falls back to the raw array length (`0` here). From Lua 5.2 on the result of the
metamethod is returned as is, even when it is a float, a string or `nil`.
The value may then be coerced by arithmetic or by `for`, or rejected by library
functions:

```lua
-- assuming the Queue and q from above
function Queue:__len()
  return self.size          -- nil: the field was never maintained
end

for i = 1, #q do end
-- Lua 5.1 / LuaJIT: no iterations, __len is never called
-- Lua 5.2 / 5.3: error: 'for' limit must be a number
-- Lua 5.4 / 5.5: error: bad 'for' limit (number expected, got nil)
```

Keep the length an integer:

```lua
function Queue:__len()
  return self.n             -- integer maintained by push()
end
```

If the length comes from outside, validate it before returning it, for example
with `assert(type(n) == "number" and n % 1 == 0, "length is not an integer")`.
`math.tointeger` is a convenient alternative on Lua 5.3+.

## Other metamethods

- `__eq`, `__lt` and `__le` results are converted to booleans by truthiness,
  so `return 0` means **true**. A metamethod written with C-style error codes
  can make every comparison succeed:

  ```lua
  local mt = {__eq = function(a, b) return a.id == b.id and 1 or 0 end}
  local a = setmetatable({id = 1}, mt)
  local b = setmetatable({id = 2}, mt)
  print(a == b)   -- true: 0 is a truthy value in Lua
  ```

  Return a real boolean instead: `return a.id == b.id`.

- `__concat` is expected to return a string. Returning a table does not raise
  at the `..` that invoked the metamethod; the table simply becomes the result
  and fails on the next concatenation.

- `__index`, `__call` and arithmetic metamethods have no fixed result type, so
  there is no type contract to violate there. Validate the returned value where
  it is used.
