---
layout: pitfall
title: "loadstring() and io.popen() on untrusted input allow code injection"
permalink: /p/L1050/
description: >-
  `load`/`loadstring` compile a string into a function and `io.popen`/`os.execute`
  run a shell command. If the string or command is built from input that a user
  can influence, an attacker can execute arbitrary code.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local expr = "1 + 1"
print(loadstring(expr)())   -- 2

-- expr arrives from a request instead:
local expr = 'os.execute("rm -rf /")'
loadstring(expr)()          -- runs the command
```

Avoid evaluating strings altogether: parse the input, validate it against a
whitelist, and dispatch through a table of allowed operations. When loading
files, reject binary chunks so malicious bytecode is not trusted:

```lua
-- Lua 5.2+: load source text only and isolate the environment.
local chunk, err = load(source, "chunk", "t", {})
if not chunk then
  return nil, err
end
```

`loadstring` exists only in Lua 5.1/LuaJIT; Lua 5.2 renamed it to `load` and
removed the bytecode verifier, so `load`/`loadfile` must be restricted to text
chunks when the data is untrusted.
