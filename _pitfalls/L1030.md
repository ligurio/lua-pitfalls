---
layout: pitfall
title: "Method definitions and calls must agree on '.' or ':'"
permalink: /p/L1030/
description: >-
  The colon syntax is only sugar for passing the receiver as the first
  argument. Defining a method with a dot and calling it with a colon (or the
  other way around) silently omits or misassigns `self`, so the method sees a
  `nil` receiver and raises "attempt to index a nil value (local 'self')".
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local account = {balance = 100}

function account.withdraw(amount)   -- defined with '.': no implicit self
  self.balance = self.balance - amount
end

account:withdraw(10)
-- Runtime error: attempt to index a nil value (global 'self')
```

`account:withdraw(10)` is sugar for `account.withdraw(account, 10)`: the
receiver is passed as an extra first argument. The function above declares
only `amount`, so the table value lands in `amount` while `self` stays `nil`
(and since it is not declared, it resolves to a global). Declare the method
with a colon to add the implicit `self` parameter:

```lua
function account:withdraw(amount)
  self.balance = self.balance - amount
end

account:withdraw(10)
print(account.balance)   -- 90
```

The reverse mix-up fails the same way: a function defined with `:` always
expects a receiver, so calling it with `.` leaves `self` unset.

```lua
local stack = {}

function stack:reset()
  self.items = {}   -- self is the implicit first argument
end

stack:reset()    -- self = stack
stack.reset()    -- forgot the receiver: self is nil
-- Runtime error: attempt to index a nil value (local 'self')
```

Method calls on a literal also need parentheses, because `:` cannot directly
follow a string literal:

```lua
print("abc":upper())      -- Syntax error
print(("abc"):upper())    -- "ABC"
```

This is a runtime error rather than a style issue; linting does not reliably
catch an arity mismatch between the definition and the call site.
