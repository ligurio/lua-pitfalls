---
layout: pitfall
title: "An unclosed file leaks a descriptor"
permalink: /p/L1048/
description: >-
  `io.open`, `io.popen` and `io.tmpfile` return handles backed by operating
  system file descriptors. Lua does not close them automatically, so forgetting
  `:close()` eventually exhausts the descriptor table and the process fails with
  "too many open files".
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local function read_all(path)
  local fh = io.open(path, "r")    -- never closed
  return fh:read("*a")
end

for i = 1, 100000 do
  read_all("/etc/hosts")
end
-- eventually: too many open files
```

Close every handle on all paths, including the error path. In Lua 5.4 the
`<close>` attribute ties the lifetime of the handle to the enclosing scope:

```lua
local function read_all(path)
  local fh <close> = assert(io.open(path, "r"))
  return fh:read("*a")
end
```

Handles returned by `io.popen` and `io.tmpfile` leak the same way and must be
closed explicitly.
