---
layout: pitfall
title: "Numbers above 2^53 lose precision"
permalink: /p/L1061/
description: >-
  In Lua 5.1, 5.2 and LuaJIT every number is a double, so integers beyond
  2^53 (9007199254740992) are no longer represented exactly. Distinct literals
  can compare equal and arithmetic silently returns a rounded value. Use cdata
  for exact 64-bit integers.
runtime:
  - Lua 5.1
  - Lua 5.2
  - LuaJIT
analyzers:
  - semgrep
---

```lua
print(9007199254740993)                     -- 9.007199254741e+15
print(9007199254740993 == 9007199254740992) -- true

print(2^53 + 1 == 2^53)                     -- true
print(9223372036854775807)                  -- 9.2233720368548e+18, rounded
```

In LuaJIT/Tarantool exact 64-bit values are cdata produced by the `LL`/`ULL`
suffix or `ffi.new`:

```lua
local ffi = require("ffi")

local a = 9007199254740993ULL              -- exact unsigned 64-bit
local b = 9007199254740993LL               -- exact signed 64-bit
local c = ffi.new("int64_t", 1) + a
print(a)                                   -- 9007199254740993ULL
print(b)                                   -- 9007199254740993LL
```

Note that `math.*` does not accept cdata (see
[L1062]({{ '/p/L1062/' | relative_url }})), so 64-bit arithmetic is done with
LuaJIT operators or the FFI. Lua 5.3 and later have a 64-bit integer subtype,
where integer literals and arithmetic stay exact; only values converted to
floats lose precision.
