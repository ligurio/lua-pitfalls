---
layout: pitfall
title: "math.* does not accept cdata"
permalink: /p/L1062/
description: >-
  The standard `math` library expects Lua numbers. Passing a cdata integer
  (uint64/int64) raises "number expected, got cdata", so 64-bit values cannot be
  processed with `math.floor`, `math.abs`, `math.max` and friends.
runtime:
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local ffi = require("ffi")

local x = ffi.new("uint64_t", 2)
print(math.floor(x))
-- error: bad argument #1 to 'floor' (number expected, got cdata)
```

Use arithmetic operators on the cdata (LuaJIT implements the usual operators for
integer cdata) or convert to a number when the value fits a double:

```lua
local ffi = require("ffi")

local x = ffi.new("uint64_t", 2)
local y = x * 3 + 1            -- arithmetic works on cdata
print(tostring(y))             -- 7ULL

local n = tonumber(x)          -- safe only while |value| <= 2^53
print(math.floor(n / 2))
```

For comparisons the ordinary operators also work (`x < y`, `x == y`). Values
beyond 2^53 must stay cdata; see
[L1061]({{ '/p/L1061/' | relative_url }}).
