---
layout: pitfall
title: "Lua arrays are 1-based"
permalink: /p/L1003/
description: >-
  Lua indexes arrays and strings starting at 1, not 0. The first element of a
  table is `t[1]`, `t[0]` is nil unless assigned, and the length operator `#t`
  counts from index 1. This is a common source of off-by-one errors for
  programmers coming from zero-based languages.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local t = {10, 20, 30}

print(t[1])   -- 10
print(t[0])   --> nil, not 10!
print(#t)     -- 3

-- Off-by-one: reads t[0] and skips t[1].
for i = 0, #t do
  print(t[i])
end

-- Correct: indices run from 1 to #t.
for i = 1, #t do
  print(t[i])
end
```

The same applies to strings: `string.sub("abc", 1, 1)` returns `"a"`, and
`string.sub("abc", 0, 1)` returns an empty string.
