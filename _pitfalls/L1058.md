---
layout: pitfall
title: "Not every operation is JIT-compiled under LuaJIT"
permalink: /p/L1058/
description: >-
  LuaJIT's compiler does not implement every Lua construct. When a trace meets a
  not-yet-implemented (NYI) operation it aborts and the code falls back to the
  interpreter, so a hot function can silently run interpreted. Some operations
  became compilable only in LuaJIT 2.1, and `jit.off()` disables compilation
  entirely.
runtime:
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local function now()
  return os.time()            -- os.time is NYI: the trace aborts
end

local function producer()
  local co = coroutine.create(function()
    coroutine.yield()         -- coroutine.* is NYI
  end)
  coroutine.resume(co)
end
```

Calls such as `os.time`, `os.date`, `error`, `load`, `loadfile`,
`coroutine.*`, `string.dump` and most of `debug.*`, `package.*`, `ffi.cdef`,
`ffi.load`, `ffi.metatype` abort a trace. Others, like `string.format`,
`select`, `tonumber`, `table.insert` and several `ffi.*` helpers, abort only
under some circumstances ("partial compilation").

Keep NYI operations out of the innermost loops, and verify what actually gets
compiled instead of assuming that running under LuaJIT means running compiled
code:

```sh
luajit -jv  script.lua    # log trace aborts and their reasons
luajit -jdump script.lua  # dump generated machine code
```

`jit.off()` (or `jit.off(func)`) disables compilation and should be reserved
for code where a trace would be harmful, never as a general workaround for NYI
operations.
