---
layout: pitfall
title: "math.min() and math.max() give inconsistent results with NaN"
permalink: /p/L1094/
description: >-
  LuaJIT's math.min() and math.max() handle a NaN argument inconsistently: the
  result depends on the order of the arguments and on the host architecture,
  so an expression that looks commutative can produce different values on
  different machines.
runtime:
  - LuaJIT
---

```lua
local nan = 0 / 0

print(math.min(1, math.max(nan, 1)))
print(math.min(1, math.max(1, nan)))
-- the two lines can print different values on x86_64
```

With NaN, comparisons are neither true nor false, and the implementation of
`math.min`/`math.max` may use a sequence of comparisons whose outcome depends
on how the operands are ordered. The reference manual leaves the behaviour
unspecified when NaN is involved, so code should never feed NaN into these
functions and expect a deterministic result.

Validate the inputs before comparing, or filter NaN explicitly:

```lua
local function safe_max(a, b)
  if a ~= a then return b end    -- a is NaN
  if b ~= b then return a end    -- b is NaN
  return a > b and a or b
end
```

`x ~= x` is the portable NaN test. The same caveat applies to any comparison
that can see NaN.
