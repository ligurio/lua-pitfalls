---
layout: pitfall
title: "Recursive local functions need the local function statement"
permalink: /p/L1031/
description: >-
  `local function f` declares `f` before compiling the body, so the function
  can call itself. Writing `local f = function` instead compiles the body
  first: at that point `f` is still a global, so the recursive call hits a
  nil value and raises "attempt to call a nil value (global 'f')".
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - luacheck
  - selene
---

```lua
local fact = function(n)
  if n == 0 then
    return 1
  end
  return n * fact(n - 1)   -- 'fact' is not in scope yet
end

print(fact(5))
-- Runtime error: attempt to call a nil value (global 'fact')
```

`local f = function() ... end` evaluates the right-hand side before the local
`f` comes into scope, so inside the body the name `f` resolves to a global.
The named form introduces the local first and supports recursion:

```lua
local function fact(n)
  if n == 0 then
    return 1
  end
  return n * fact(n - 1)   -- refers to the local
end

print(fact(5))   -- 120
```

If you need to assign the function later, declare the local separately:

```lua
local fact
fact = function(n)
  if n == 0 then return 1 end
  return n * fact(n - 1)
end
```

`luacheck` and `selene` report the access to the undefined global `fact`.
