---
layout: pitfall
title: "A null cdata compares equal to nil but is truthy"
permalink: /p/L1059/
description: >-
  In LuaJIT a null pointer is represented by cdata. Comparison with `nil`
  returns true, yet the value passes a boolean test, because only `false` and
  `nil` are falsy. Equality and truthiness disagree, so `x == nil` and `if x`
  can give opposite answers for the same value.
runtime:
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local ffi = require("ffi")

local p = ffi.cast("void *", 0)   -- a null pointer

print(p == nil)     -- true
print(nil == p)     -- true
print(not not p)    -- true
if p then
  print("branch taken")   -- taken: a null pointer is truthy
end
```

`ffi.new("int", 0)` behaves the same way: its value is zero, but the object is
not `false` or `nil`, so it is truthy and also compares equal to `nil` when it
is a pointer type.

Never use truthiness to test whether a pointer or a nullable cdata holds a
value. Compare explicitly:

```lua
if p == nil then
  print("null pointer")    -- true for p above
end

if p ~= nil then
  print("not reached")
end
```

Tarantool's `box.NULL` is a value of this kind; see
[T1027]({{ '/t/T1027/' | relative_url }}) for its consequences in the box API.
