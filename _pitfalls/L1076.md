title: "A discarded return value silently does nothing"
permalink: /p/L1076/
description: >-
  Many functions do not modify their argument; they return a new value. Calling
  one and ignoring the result looks like it had an effect but changes nothing,
  because Lua never warns that a returned value was dropped.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5

  - emmylua-analyzer

```lua
local name = "lua"

name:upper()          -- returns "LUA", but the result is thrown away
print(name)           -- "lua": strings are immutable

local upper = name:upper()
print(upper)          -- "LUA"
```

String methods such as `upper`, `gsub` and `rep` return a new string; they never
change the original. The same pattern applies to any function that computes and
returns a value rather than mutating a table in place:

```lua
local function reversed(t)      -- builds and returns a new table
  local copy = {}
  for i = #t, 1, -1 do
    copy[#copy + 1] = t[i]
  end
  return copy
end

local nums = {1, 2, 3}
reversed(nums)                  -- the returned table is discarded
print(nums[1])                  -- 1: the original is unchanged

local rev = reversed(nums)
print(rev[1])                   -- 3
```

Assign the result whenever the function is documented to return one. If a result
is genuinely unneeded, discard it explicitly to show intent:

```lua
local _, err = pcall(work)      -- keep the error, ignore the status
```

EmmyLua's `discard-returns` diagnostic flags calls to functions annotated with
`---@nodiscard`, so a forgotten assignment is caught at the call site. The same
habit matters for error handling: a return value that reports failure is easy to
ignore, as in [L1043]({{ '/p/L1043/' | relative_url }}).
