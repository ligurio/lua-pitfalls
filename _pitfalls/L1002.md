---
layout: pitfall
title: "Shadowing and overwriting the standard library"
permalink: /p/L1002/
description: >-
  Lua lets you reuse the names of the standard library globals. Declaring a
  `local` with the same name as a global (e.g. `string`) silently shadows it
  for the rest of the scope, while reassigning a global (e.g. `print = "Hello"`)
  overwrites it for the whole process. Both break every later use of the
  function, locally or in every module that shares the environment.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - luacheck
  - selene
---

```lua
local string = "some value"  -- shadows the string library for this file

-- Error: attempt to index a string value (global 'string')
local substring = string.sub("hello", 1, 3)
```

The local `string` makes every later call such as `string.format()`,
`string.gsub()` or `string.sub()` fail with a confusing "attempt to index"
error, or silently behave differently when the shadowing value happens to be
a table.

Reassigning a global is worse: it overwrites the built-in for the whole
process, and modules share the global environment:

```lua
print = "Hello"      -- overwrites the built-in for the whole process
print("Test")        -- Error: attempt to call a string value
```

Avoid shadowing standard library names:

```lua
local value = "some value"

local substring = string.sub("hello", 1, 3)
```

If you need to override a function, keep it inside one scope with a `local`:

```lua
local print = function(msg) log("[log]", msg) end
print("Test")   -- calls the local; the global stays intact
```

`luacheck` and `selene` report shadowed standard library globals. To sandbox
untrusted code, run it in an isolated environment (`setfenv()` on Lua 5.1,
`_ENV` on Lua 5.2+) instead of mutating the shared globals, e.g. with a
metatable that guards `__index`/`__newindex`.
