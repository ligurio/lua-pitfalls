---
layout: pitfall
title: "Redeclaring a local silently shadows the previous one"
permalink: /p/L1074/
description: >-
  A second `local` with the same name does not assign to the existing variable:
  it introduces a new one that shadows the old for the rest of the block.
  Assignments to the inner variable leave the outer one untouched, which hides
  copy-paste mistakes and broken updates.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - luacheck
  - selene
  - emmylua-analyzer
---

```lua
local value = 10

local function compute()
  local value = 20   -- a new variable, not an update of the outer one
  return value
end

print(compute())   -- 20
print(value)       -- 10: the outer variable was never changed
```

The same name declared twice in the same block creates two variables; later code
sees only the newest:

```lua
local x = 1
local x = 2        -- shadows the previous 'x' from here on
print(x)           -- 2
```

Assign without `local` when you mean to update an existing variable, and use
distinct names for distinct values:

```lua
local value = 10

local function compute()
  value = value * 2
  return value
end

print(compute())   -- 20
print(value)       -- 20
```

Shadowing is not always wrong - `local x = x` deliberately captures an outer
`x` - but an unintentional redefinition is a common source of stale-value bugs.
`luacheck` and `selene` report shadowed locals, and `selene` has a dedicated
`shadowing` lint.
