---
layout: pitfall
title: "Deleting an array element leaves a hole"
permalink: /p/L1017/
description: >-
  Setting an array element to `nil` deletes it but does not shift the later
  elements. The table keeps the remaining values at their original indices, so
  the array part is no longer contiguous: the values after the hole behave
  like dictionary keys, and both `#t` and `ipairs()` stop seeing them.
  Iterating `for i = 1, #t` then silently skips part of the array. To actually
  remove an element and keep the array dense, use `table.remove()`.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local t = {"a", "b", "c", "d"}

t[2] = nil       -- delete index 2; c and d do NOT shift

print(t[1], t[2], t[3], t[4])   -- a nil c d
print(#t)                       -- undefined: may print 1 or 4

for i, v in ipairs(t) do        -- stops at the hole: only "a" is visited
  print(i, v)
end

for i, v in pairs(t) do         -- still sees all remaining keys
  print(i, v)                   -- 1 a / 3 c / 4 d (order not guaranteed)
end
```

To remove an element and keep the array contiguous, use `table.remove()`:

```lua
local t = {"a", "b", "c", "d"}

table.remove(t, 2)   -- shifts c and d down

for i, v in ipairs(t) do
  print(i, v)        -- a c d
end
print(#t)            -- 3
```

`t[i] = nil` is fine for dictionaries, but for a list it turns the elements
after the hole into entries that `#t` and `ipairs()` no longer cover, which
silently skips part of the array. See also [L1004]({{ '/p/L1004/' | relative_url }})
and [L1005]({{ '/p/L1005/' | relative_url }}).
