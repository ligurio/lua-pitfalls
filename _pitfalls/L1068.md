---
layout: pitfall
title: "os.execute returns a number in 5.1 but a status triple in 5.2+"
permalink: /p/L1068/
description: >-
  In Lua 5.1 and LuaJIT `os.execute` returns the exit status as a number, while
  in Lua 5.2 and later it returns `true` or `nil, reason, code`. Code that
  compares the result with `0` breaks on newer interpreters.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local status = os.execute("test -f /etc/hosts")

if status == 0 then
  print("exists")
end
-- Lua 5.1 / LuaJIT: status is 0, the branch runs.
-- Lua 5.2+:        status is true, so 0 == true is false: the branch never runs.
```

Lua 5.1 and LuaJIT return the raw status number. Since Lua 5.2, `os.execute`
returns `true` on success, or `nil, "exit"|"signal", code` on failure:

```lua
local ok, reason, code = os.execute("test -f /etc/hosts")
print(ok, reason, code)
-- 5.1 / LuaJIT: 0  nil  nil
-- 5.2+:         true  exit  0
```

Write the check portably, or do not use the exit status at all when only the
side effect matters:

```lua
local ok, reason, code = os.execute("test -f /etc/hosts")

local succeeded = ok == true or ok == 0
if not succeeded then
  io.stderr:write(("command failed: %s %s\n"):format(
    tostring(reason), tostring(code)))
end
```

The version split is specific to `os.execute`; on Lua 5.1 and LuaJIT there is no
portable way to get `reason` and `code`. When the status matters, isolate the
call behind a small helper so the conditional lives in one place. See
[L1011]({{ '/p/L1011/' | relative_url }}) for why `0 == true` is silently
`false`.
