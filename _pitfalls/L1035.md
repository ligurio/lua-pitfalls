---
layout: pitfall
title: "io.open() and friends return nil on failure instead of raising"
permalink: /p/L1035/
description: >-
  Library functions such as `io.open`, `os.getenv` and `tonumber` signal
  failure by returning `nil` (usually with a second error message) rather than
  raising. Forgetting to check the first result leads to a later "attempt to
  index a nil value" at an unrelated line.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local f = io.open("missing.txt", "r")
local line = f:read("l")
-- Runtime error: attempt to index a nil value (local 'f')
```

`io.open` returns `nil, errmsg` when the file cannot be opened, so the failure
surfaces only later, when the handle is used. The same pattern applies to
`os.getenv` (`nil` when the variable is unset) and `tonumber` (`nil` when the
string is not a number):

```lua
local f, err = io.open("missing.txt", "r")
if not f then
  print("cannot open: " .. err)
  return
end

local n = assert(tonumber("12abc"), "not a number")
```

Check the first return value before using it, or wrap the call in `assert`.
