title: "Calling a function with the wrong number of arguments is not an error"
permalink: /p/L1073/
description: >-
  Lua does not check how many arguments a call passes. Missing arguments become
  `nil` and extra ones are silently discarded, so an arity mistake surfaces only
  later, when the function tries to use a parameter that was never supplied.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - emmylua-analyzer
---

```lua
local function greet(name, greeting)
  return greeting .. ", " .. name
end

print(greet("world"))
-- Runtime error: attempt to concatenate a nil value (local 'greeting')

print(greet("world", "Hello", "!"))   -- "Hello, world": "!" is ignored
```

A call adjusts its arguments to the function's parameters: missing values are
filled with `nil` and extra values are dropped. The error appears inside the
callee, often far from the call site that actually made the mistake.

Pass every parameter explicitly, and give the function a default or a check when
the argument is optional:

```lua
local function greet(name, greeting)
  greeting = greeting or "Hello"
  return greeting .. ", " .. name
end

print(greet("world"))   -- "Hello, world"
```

For variadic functions, `select("#", ...)` returns the real argument count, so
`nil` arguments can be distinguished from absent ones. Static analyzers compare
the call against the known signature and report missing or redundant arguments.
