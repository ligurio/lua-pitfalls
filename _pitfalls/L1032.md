---
layout: pitfall
title: "The and/or idiom is not a safe ternary operator"
permalink: /p/L1032/
description: >-
  `cond and a or b` looks like a ternary, but `and`/`or` return their operands,
  not booleans. When `a` is `false` or `nil`, the `or b` branch is taken even
  though the condition was true, silently returning the wrong value.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local function pick(cond, a, b)
  return cond and a or b
end

print(pick(true, "yes", "no"))    -- yes
print(pick(true, false, "no"))    -- no   expected false
print(pick(true, nil, "no"))      -- no   expected nil
print(pick(false, "yes", "no"))   -- no
```

`cond and a` evaluates to `a` only when `cond` is truthy and `a` is itself
truthy; otherwise the `or b` fallback fires. Use an explicit branch when the
true result can be falsy:

```lua
local function pick(cond, a, b)
  if cond then
    return a
  else
    return b
  end
end
```

The compact idiom is safe only when the true-branch value is guaranteed to be
truthy. See also [L1011]({{ '/p/L1011/' | relative_url }}).
