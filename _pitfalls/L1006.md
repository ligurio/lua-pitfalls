---
layout: pitfall
title: "Forgetting `local` creates a global"
permalink: /p/L1006/
description: >-
  Assigning to an undeclared variable creates a new global instead of raising
  an error. A forgotten `local` or a typo silently pollutes the global table
  and can cause subtle, cross-function bugs that are hard to reproduce.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - luacheck
  - selene
---

```lua
local function compute()
  result = 42   -- forgot `local`: creates a global
  return result
end

compute()
print(result)   -- 42: the global leaked out of the function
```

`luacheck` and `selene` report writes to undefined globals, so a missing
`local` is caught before it bites. With LuaJIT, accessing a missing global
also triggers the `__index` handler of the `_G` metatable, which many
projects abuse for sandboxing.
