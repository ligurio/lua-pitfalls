layout: pitfall
title: "io.write failures are silently ignored"
permalink: /p/L1069/
description: >-
  `io.write` and `file:write` return the file on success but `nil, err` on
  failure. Ignoring the result hides a full disk, a closed pipe or a read-only
  handle, and the program continues as if the data was written.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
io.write("important record\n")   -- result discarded
-- If stdout is a closed pipe or the disk is full, the write fails and
-- nothing tells the program about it.
```

`write` reports failure through its return value, so check it:

```lua
local ok, err = io.write("important record\n")
if not ok then
  io.stderr:write("write failed: " .. tostring(err) .. "\n")
end
```

Two related surprises:

- `print` appends a newline and uses `tostring`; `io.write` writes exactly what
  it is given and requires a string or number, so records run together without
  an explicit `"\n"`.
- On Lua 5.1/LuaJIT a successful write returns `true`; on Lua 5.2+ it returns
  the file object. Either way the failure value is `nil, err`.

For files, a failed write leaves the handle usable but the data is lost; close
and check `file:close()` as well, since buffered data is flushed on close:

```lua
local fh = assert(io.open("out.txt", "w"))
local ok, err = fh:write("data")
if not ok then
  fh:close()
  error("write failed: " .. tostring(err))
end
assert(fh:close())
```
