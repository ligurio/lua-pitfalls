---
layout: pitfall
title: "Using a file handle after close()"
permalink: /p/L1047/
description: >-
  `close()` releases the underlying descriptor. Any later `:read()`, `:write()`,
  `:seek()` or a second `close()` on the same handle fails with
  "attempt to use a closed file".
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local fh = io.open("data.txt", "r")
local first = fh:read("*a")
fh:close()

local second = fh:read("*a")
-- Runtime error: attempt to use a closed file
```

Read everything needed before closing, or reopen the file. `io.lines` and
`io.popen` handles behave the same way:

```lua
local fh = io.open("data.txt", "r")
local first = fh:read("*a")
fh:close()

local fh2 = assert(io.open("data.txt", "r"))
local second = fh2:read("*a")
fh2:close()
```

Calling `close()` twice is also an error; a handle is single-use. In Lua 5.4 a
`<close>` variable closes the handle automatically when it leaves scope and
prevents use-after-close by construction.
