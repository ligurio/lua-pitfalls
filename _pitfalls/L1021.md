---
layout: pitfall
title: "Recursion overflows the stack without a tail call"
permalink: /p/L1021/
description: >-
  Lua guarantees proper tail calls: when a function returns exactly the result
  of a call in tail position, the call runs without growing the stack. A
  recursive function that is not tail-recursive (the result is used after the
  call, e.g. `return n * factorial(n - 1)`) consumes one stack frame per
  recursion level and overflows for deep recursion. Rewrite the recursion to
  put the call in tail position, passing the accumulator as an argument.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
function factorial(n)
  if n == 0 then
    return 1
  else
    return n * factorial(n - 1)   -- not a tail call: multiplies after the call
  end
end

print(factorial(10000))   -- Stack overflow!
```

`return n * factorial(n - 1)` is not a tail call because the multiplication
runs after the recursive call returns, so each level keeps a live frame on the
stack. A call in tail position is the very last operation of the function and
runs without growing the stack:

```lua
function factorial(n, acc)
  acc = acc or 1
  if n == 0 then
    return acc
  end
  return factorial(n - 1, n * acc)   -- tail call: nothing runs after it
end

print(factorial(10000))   -- constant stack usage
```

Lua guarantees proper tail calls for all such calls (LuaJIT implements them
too). Note that the exact numeric result of `10000!` is out of range here; the
point of the example is the stack usage, not the value.
