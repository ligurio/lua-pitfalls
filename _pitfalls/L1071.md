title: "assert(0) passes: only false and nil fail"
permalink: /p/L1071/
description: >-
  `assert` raises only when its first argument is `false` or `nil`. Values that
  are false in other languages, such as `0` and the empty string, are truthy,
  so `assert(0)` succeeds and a failed check goes unnoticed.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
assert(0)          -- passes: 0 is truthy
assert("")         -- passes: the empty string is truthy
assert(false)      -- error: assertion failed!
assert(nil)        -- error: assertion failed!
```

This bites when `assert` guards a function that reports failure through a
falsy-looking but truthy value:

```lua
local n = tonumber("  12 ")   -- 12, fine
assert(n)                     -- ok

local m = tonumber("12x")     -- nil on failure
assert(m)                     -- error, as expected

local count = 0
assert(count)                 -- passes even though count is zero
```

Use an explicit comparison when zero or empty must be rejected, and remember
that the error message is always evaluated:

```lua
local count = 0
assert(count ~= 0, "count must be positive")

-- the message expression is evaluated even on success:
assert(ok, ("operation failed: %s"):format(tostring(err)))
```

The other well-known behaviour is that `assert` returns all of its arguments, so
`local fh = assert(io.open(path))` is a compact way to unwrap `nil, err`. See
[L1011]({{ '/p/L1011/' | relative_url }}) for the underlying truthiness rules.
