---
layout: pitfall
title: "__pairs and __ipairs are ignored in LuaJIT"
permalink: /p/L1063/
description: >-
  Lua 5.2 added the `__pairs` and `__ipairs` metamethods so that `pairs` and
  `ipairs` can be customized. LuaJIT implements the Lua 5.1 behaviour and never
  calls them, so a proxy table that relies on these metamethods iterates its raw
  contents instead.
runtime:
  - LuaJIT
analyzers:
  - semgrep
---

```lua
local proxy = setmetatable({10, 20, 30}, {
  __pairs = function()
    return function() end          -- hides everything in Lua 5.2+
  end,
  __ipairs = function()
    return function() end
  end,
})

for k, v in pairs(proxy) do
  print(k, v)   -- 1 10, 2 20, 3 30: LuaJIT ignores __pairs
end

for i, v in ipairs(proxy) do
  print(i, v)   -- 1 10, 2 20, 3 30: __ipairs is ignored too
end
```

`pairs` and `ipairs` use the raw table access in LuaJIT, so the metamethods are
dead code. Provide an explicit iterator instead of relying on them:

```lua
local proxy = {}

function proxy:iter()
  local keys = {"a", "b", "c"}
  local i = 0
  return function()
    i = i + 1
    if keys[i] then
      return keys[i], self[keys[i]]
    end
  end
end

for k, v in proxy:iter() do
  print(k, v)
end
```

The same applies to other Lua 5.2 features that LuaJIT does not implement; check
the LuaJIT status page before using newer-language constructs.
