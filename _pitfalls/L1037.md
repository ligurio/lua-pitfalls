---
layout: pitfall
title: "Length and indices count bytes, not UTF-8 characters"
permalink: /p/L1037/
description: >-
  Lua strings are byte arrays. The length operator `#`, `string.sub`,
  `string.find` and friends all use byte offsets, so on non-ASCII text they do
  not match the number of characters and can split a multi-byte sequence. Use
  the `utf8` library (Lua 5.3+) to work with code points.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local s = "héllo"

print(#s)                 -- 6: bytes, not characters

print(s:sub(1, 2))        -- "h\195": cuts the two-byte 'é' in half
```

`#s` returns the number of bytes, and `string.sub(s, 1, 2)` slices by byte
offset, which can produce an invalid UTF-8 string. The `utf8` library, added
in Lua 5.3, works on code points and is the right tool for text:

```lua
local s = "héllo"

print(utf8.len(s))        -- 5
print(utf8.offset(s, 3))  -- 3: byte offset of the third code point

for pos, code in utf8.codes(s) do
  io.write(pos, "=", utf8.char(code), " ")
end
-- 1=h 2=é 4=l 5=l 6=o
```

On Lua 5.1, Lua 5.2 and LuaJIT the `utf8` library is unavailable; use a
third-party UTF-8 module if you need code-point semantics.
