---
layout: pitfall
title: "Modifying a table while iterating over it"
permalink: /p/L1019/
description: >-
  Removing elements from an array while iterating forward with `ipairs()` (or
  a `for i = 1, #t` loop) silently skips entries: `table.remove()` shifts every
  later element down by one, so the loop counter jumps over the element that
  moved into the removed position. Iterate backward, or collect the indices
  first and remove them afterwards.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local t = {"a", "b", "b", "c"}

for i, v in ipairs(t) do
  if v == "b" then
    table.remove(t, i)   -- shifts the rest down by one
  end
end

print(table.concat(t, ", "))   -- "a, b, c": the second "b" was skipped
```

`table.remove()` compacts the array, so removing forward skips the element
that shifts into the removed position. Iterate backward instead:

```lua
local t = {"a", "b", "b", "c"}

for i = #t, 1, -1 do           -- iterate backward
  if t[i] == "b" then
    table.remove(t, i)
  end
end

print(table.concat(t, ", "))   -- "a, c"
```

The same applies to any mutation that changes the length while a `for i = 1,
#t` loop runs. An alternative is to collect the indices to remove first and
delete them afterwards in reverse order. See also [L1017]({{ '/p/L1017/' | relative_url }}).
