title: "Code after return, break or error is unreachable"
permalink: /p/L1054/
description: >-
  Statements that follow a `return`, `break`, `goto` or `error` in the same
  block can never run. They are dead code that misleads the reader and often
  hides a copy-paste mistake.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - semgrep
  - luacheck
  - emmylua-analyzer
---

```lua
local function cbrt(v)
  if v >= 0 then
    return v ^ (1 / 3)
  else
    error("cbrt expects a non-negative argument")
  end

  return 0            -- unreachable: both branches exit
end
```

Both branches of the `if` leave the function, so the trailing `return 0` is
never evaluated. Remove it, or restructure the function so every path is
reachable:

```lua
local function cbrt(v)
  if v < 0 then
    error("cbrt expects a non-negative argument")
  end
  return v ^ (1 / 3)
end
```

`return` must be the last statement of a block, so `return 0; print("x")` is a
syntax error. Unreachable code is harder to spot after a control-flow statement
whose branches all exit, as above, because it parses fine and only the analysis
of all paths reveals that it never runs.
