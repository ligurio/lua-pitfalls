---
layout: pitfall
title: "ffi.cdef must match the real C declaration"
permalink: /p/L1067/
description: >-
  `ffi.cdef` does not read C headers; it re-declares the interface in LuaJIT's
  own parser. A declaration that differs from the compiled C code (wrong integer
  size, signedness or struct layout) is accepted silently and then passes wrong
  values or reads wrong field offsets.
runtime:
  - LuaJIT
analyzers:
  - semgrep
---

The C library was compiled with one declaration, the FFI uses another:

```lua
local ffi = require("ffi")

-- The header says:  void set_timeout(long seconds);
-- On 64-bit Linux long is 8 bytes, but int is 4.
ffi.cdef[[
    void set_timeout(int seconds);
]]

ffi.C.set_timeout(1)
-- The callee reads a 64-bit argument, but only 32 bits were supplied.
```

Struct declarations are worse, because a wrong field type changes the size and
the offset of everything after it:

```lua
local ffi = require("ffi")

-- The header says:  struct sample { int id; double value; };
-- Declaring value as float shifts the layout and truncates the data.
ffi.cdef[[
    struct sample {
        int id;
        float value;   -- wrong: should be double
    };
]]
```

LuaJIT trusts the declaration; there is no comparison against the actual ABI.
Copy declarations verbatim from the headers, keep them in one place, and verify
the result where it matters:

```lua
local ffi = require("ffi")

ffi.cdef[[
    struct sample {
        int id;
        double value;
    };
]]

assert(ffi.sizeof("struct sample") == 16)   -- catch layout drift early
assert(ffi.abi("64bit"))                    -- branch on the target ABI if needed
```

Portability matters too: `long`, `size_t` and pointers have different sizes on
32-bit and 64-bit targets, so a declaration copied from one platform can be
wrong on another.
