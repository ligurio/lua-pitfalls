---
layout: pitfall
title: "Assigning a table copies the reference, not the table"
permalink: /p/L1018/
description: >-
  Tables are reference types: `local b = a` does not copy the table, it makes
  `b` an alias for the same object. Assigning a table into a field stores a
  reference too, so two parts of the program can silently end up editing the
  same table. To get an independent copy, build one explicitly: a shallow copy
  with a loop or `table.move()`, or a recursive deep copy when the table
  contains nested tables.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
local a = {x = 10}
local b = a            -- b is the same table, not a copy

b.x = 99
print(a.x)             -- 99: a was modified too
```

Nested tables are shared the same way:

```lua
local config = {speed = 1, pos = {x = 0, y = 0}}

local player = config.pos   -- a reference, not a copy
player.x = 100

print(config.pos.x)         -- 100: the original was edited too
```

Build an explicit copy when you need an independent table:

```lua
local a = {x = 10}

-- Shallow copy:
local b = {}
for k, v in pairs(a) do b[k] = v end

b.x = 99
print(a.x)   -- 10: a is untouched
```

A shallow copy is enough for flat tables. If the table contains nested
tables, copy them recursively (a deep copy); `table.move()` is a convenient
option for array parts on Lua 5.2+. See also [L1010]({{ '/p/L1010/' | relative_url }}).
