---
layout: pitfall
title: "setfenv(), loadstring() and table.getn() removed in Lua 5.2"
permalink: /p/L1014/
description: >-
  `setfenv()`, `getfenv()` and `loadstring()` existed in Lua 5.1, and
  `table.getn()` was already deprecated there. All of them are undefined on
  Lua 5.2+, and `table.getn()` is deprecated in LuaJIT too, which keeps the
  5.1 functions for compatibility. Portable code must use `_ENV`, `load()` and
  the length operator `#` instead.
runtime:
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
analyzers:
  - luacheck
  - selene
---

```lua
-- Lua 5.1 / LuaJIT:
local f = loadstring("return 1 + 1")

-- Lua 5.2+: attempt to call global 'loadstring' (a nil value)
-- Portable:
local f = load("return 1 + 1")
```

```lua
-- Lua 5.1 / LuaJIT (deprecated since 5.1):
local n = table.getn({1, 2, 3})

-- Preferred on every version:
local n = # {1, 2, 3}
```

`setfenv()`/`getfenv()` had no direct replacement; on 5.2+ environment handling
goes through the `_ENV` upvalue. `luacheck` and `selene` flag these as
undefined globals when targeting 5.2+.

LuaJIT keeps `loadstring()`, `setfenv()` and `table.getn()` because it is based
on Lua 5.1, but `table.getn()` is deprecated even there: prefer the `#`
operator, which works on every version.
