---
layout: pitfall
title: "string.sub and string.byte clamp out-of-range positions instead of failing"
permalink: /p/L1072/
description: >-
  `string.sub` never raises for a bad range: positions outside the string are
  clamped, `i > j` yields the empty string, and negative indices count from the
  end. A parsing bug therefore produces a short or empty result instead of an
  error.
runtime:
  - Lua 5.1
  - Lua 5.2
  - Lua 5.3
  - Lua 5.4
  - Lua 5.5
  - LuaJIT
---

```lua
print("[" .. string.sub("abc", 10, 20) .. "]")   -- []
print("[" .. string.sub("abc", -100) .. "]")     -- [abc]
print(string.sub("hello", -3))                   -- llo
print(string.sub("hello", 2, -2))                -- ell
print(string.sub("hello", 4, 2))                 -- (empty string)
```

`string.byte` behaves the same way and returns `nil` past the end, so arithmetic
on the result fails later, far from the real mistake:

```lua
local b = string.byte("abc", 10)   -- nil
local sum = b + 1                  -- attempt to perform arithmetic on a nil value
```

Validate the range against the real string length before slicing, and decide
explicitly how negative indices should be treated:

```lua
local function slice(s, i, j)
  local n = #s
  if i < 1 or j > n or i > j then
    error(("slice %d..%d out of range for length %d"):format(i, j, n))
  end
  return string.sub(s, i, j)
end
```

Only `string.char` checks its arguments: a value outside `0..255` raises
"value out of range", which makes the asymmetry easy to forget.
